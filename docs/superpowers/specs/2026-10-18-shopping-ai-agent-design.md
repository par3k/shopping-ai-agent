# shopping-ai-agent 설계

## 의도와 이유
쇼핑몰 백엔드와 AI 챗봇을 **아키텍처 설계부터 시작해 단계별로 하나씩 만들어 간다.** 목적은 완성품이 아니라 **만들어 가는 과정을 블로그 글로 남기는 것**이다. 그래서 각 단계가 끝난 시점의 코드를 독자가 그대로 열어볼 수 있어야 한다.

- 원격 저장소: https://github.com/par3k/shopping-ai-agent.git (기본 브랜치 `main`)
- 로컬 위치: `~/Downloads/workspace/shopping-ai-agent` *(폴더명은 저장소 이름을 따른 내 결정)*

## 목표
- 서버 하나(FastAPI)로 회원/쇼핑몰/챗을 모두 제공한다. 서버를 쪼개지 않는다. 영역은 폴더로 구분한다.
- 기능을 점차 확대해 최종적으로 로그인, 상품·주문, RAG, 챗 파이프라인까지 갖춘 쇼핑 AI 에이전트를 완성한다.
- 단계마다 "여기까지 됐다"고 말할 수 있는 동작 가능한 상태로 끝낸다.

## 비목표
- 마이크로서비스 분리.
- 처음부터 전체 구조를 한 번에 만들기. 미리 만들어 둔 빈 껍데기 구조는 두지 않는다.
- sLLM 파인튜닝, n8n 연동은 이번 범위에서 다루지 않는다 *(내 결정, 필요하면 후속 단계로 추가)*.

## 안티 목표 (기술적으로 동작해도 실패인 경우)
- 단계 경계가 흐려져서, 어느 태그에서 코드를 열어도 그 단계 글의 내용과 맞지 않는 것.
- 아직 안 쓰는 기능이 미리 들어가 있어 글의 흐름을 깨는 것.

## 제약
- 기술 스택: FastAPI, SQLAlchemy, PostgreSQL(pgvector), Redis, JWT(python-jose, bcrypt), Pydantic. AI 단계에서는 OpenAI(gpt-4.1-mini, text-embedding-3-large), LangChain, LangGraph. *(스택 선택은 내 기본값, Redis는 사용자 요청)*
- Redis는 두 가지 용도로 쓴다(사용자 결정): 로그아웃 시 JWT 즉시 무효화(1단계), 챗 응답 캐시(챗 단계). Redis 장애 시 인증은 요청을 거부(503)하고, 캐시는 건너뛰고 LLM을 직접 호출한다.
- `.env`는 커밋하지 않는다. 키 이름만 문서에 적고 값은 적지 않는다.
- Docker 컨테이너·이미지는 사용자가 요청하지 않으면 조작하지 않는다. 필요한 명령어는 안내만 한다.
- 서버 테스트는 사용자의 서버와 겹치지 않는 포트로 띄우고, 직접 띄운 PID만 종료한다.

## 단계 구조 (사용자 결정)
단계는 열려 있다. **사용자가 "이 정도면 됐어"라고 말하면 그 단계가 끝난다.** 내가 먼저 종료를 선언하지 않는다. 한 단계가 너무 크면 더 쪼갤 수 있다.

| 단계 | 내용 |
|---|---|
| 1 | 서버 뼈대, DB·Redis 연결, 회원가입/로그인(JWT)/로그아웃(Redis로 즉시 무효화) |
| 2 | 기본 쇼핑몰 API: 상품·주문 조회, 구매 등 |
| 3 | RAG: 벡터 DB에 문서 수집·검색, **`/chats` 도입** (정책 질문에 답변) |
| 4 이후 | 챗이 2단계 기능을 쓰도록 QUERY/ACTION 연결, LangGraph, 실행 전 사용자 확인(HITL), 시맨틱 캐시 등을 하나씩 추가 |

4단계 이후의 순서와 범위는 정해 두지 않고, 한 단계가 끝날 때마다 사용자와 다음을 정한다.

## Git 규칙 (사용자 결정)
- 커밋 메시지: `type: 한국어 설명`. type은 `feat`, `fix`, `refactor`, `chore`, `docs`. 본문은 한국어, 끝에 Co-Authored-By 줄.
- 작업마다 브랜치(`feature/<작업>`, `chore/<작업>`)를 만들고 `main`에 `--no-ff`로 머지한 뒤 push. 커밋/push는 허락 없이 진행하고 끝에 결과를 보고한다.
- 단계가 끝나면 그 시점에 태그를 단다. 예: `step-1-login`, `step-2-api`, `step-3-rag` *(태그 이름은 내 제안)*.
- 삭제, force push 같은 되돌리기 어려운 작업은 먼저 확인한다.
- 의미 없는 메시지(`fix` 한 단어)는 쓰지 않는다.

## 빌더에게 남기는 것
- 폴더 구조, 모듈 경계, 테이블 설계, 엔드포인트 경로는 1단계 계획에서 정한다.
- 테스트 전략은 단계 계획에서 정한다.

## 내가 정한 것 (확인 필요)
1. 폴더명 `shopping-ai-agent`.
2. 파인튜닝과 n8n은 범위 밖.
3. 태그 이름 형식 `step-N-<주제>`.
4. 기술 스택은 FastAPI, SQLAlchemy, PostgreSQL(pgvector), Redis, JWT, OpenAI, LangChain/LangGraph.
5. Redis 장애 시 동작: 인증은 503으로 거부, 캐시는 건너뜀.
6. 챗 응답 캐시는 안티 목표(쓰지 않는 기능을 미리 넣지 않는다)에 따라 1단계에 넣지 않고 챗 단계에서 추가한다. 1단계는 Redis 연결과 로그아웃만 만든다.
