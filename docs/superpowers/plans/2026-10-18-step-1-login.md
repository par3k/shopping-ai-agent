# 1단계: 서버 뼈대 + 회원가입/로그인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 환경설정·DB 연결이 되는 FastAPI 서버 위에 회원가입, 로그인(JWT), 내 정보 조회(`/members/me`)를 만든다.

**Architecture:** 서버 하나, 폴더로 영역을 나눈다(`routers` → `services` → `models`). 인증은 `services/auth.py`(해시·JWT)와 `dependencies.py`(현재 회원 주입)로 분리한다. 테스트는 SQLite 인메모리 DB와 `get_db` 오버라이드로 돌려서 PostgreSQL/Docker 없이 실행된다.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2.x, PostgreSQL(운영) / SQLite(테스트), python-jose, bcrypt, Pydantic v2, pytest, httpx

**Spec:** `docs/superpowers/specs/2026-10-18-shopping-ai-agent-design.md`

## Global Constraints

- 커밋 메시지는 `type: 한국어 설명` (type: feat/fix/refactor/chore/docs), 끝에 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- 작업마다 브랜치를 만들고 `main`에 `--no-ff`로 머지한 뒤 push. 의미 없는 `fix` 한 단어 커밋 금지.
- `.env`는 커밋하지 않고, 문서에는 키 이름만 적는다.
- Docker는 조작하지 않는다. 서버를 띄워 볼 때는 8000이 아닌 포트(8001)를 쓰고 직접 띄운 PID만 종료한다.
- 이 단계에 들어가지 않는 것: 상품·주문, 챗/RAG, 로그 파일 롤링, 요청 로그 미들웨어, soft delete(`del_yn`).

## Review Focus

1. 이메일 대소문자만 다른 가입/로그인: `Kim@Example.com`으로 가입 후 `kim@example.com` 로그인이 되고, 같은 이메일 재가입은 400.
2. 응답에 비밀번호(해시 포함)가 절대 나오지 않는다.
3. Authorization 헤더 없음/깨진 토큰/만료 토큰/없는 회원의 토큰/`sub`가 숫자가 아닌 토큰은 모두 401 (500이 아니다).
4. 너무 짧은 비밀번호(8자 미만), 잘못된 이메일 형식은 422.
5. `SECRET_KEY`, `DATABASE_URL`이 없으면 서버가 시작 시점에 어떤 키가 빠졌는지 알려 주며 실패한다.

### Task 3: 회원가입/로그인/내 정보 API

**Files:**
- Create: `app/dependencies.py`, `app/routers/__init__.py`, `app/routers/member.py`, `tests/test_member_api.py`
- Modify: `app/main.py` (시작 시 `Base.metadata.create_all(bind=engine)`, 라우터 등록), `tests/conftest.py` (`get_db` 오버라이드·테이블 생성 연결)

**Interfaces:**
- Consumes: Task 2의 모델, 스키마, `hash_password`, `verify_password`, `create_access_token`, `decode_access_token`
- Produces:
  - `get_db() -> Iterator[Session]`
  - `get_current_member(...) -> Member` — `HTTPBearer(auto_error=False)`를 쓰고, 헤더 없음/잘못된 토큰/`sub`가 정수가 아님/회원 없음은 모두 401 (`detail`: `"Not authenticated"`, `"Invalid token"`, `"Member not found"`)
  - `POST /members/signup` → 201 `MemberResponse`; 이메일 중복이면 400 `"Email already registered"`
  - `POST /members/login` → 200 `TokenResponse`; 실패는 이메일 유무와 상관없이 401 `"Invalid email or password"`
  - `GET /members/me` → 200 `MemberResponse`
  - 이메일은 저장·조회 전에 소문자로 정규화한다.

- [ ] **Step 1: 실패하는 테스트 작성** — `tests/test_member_api.py` (헬퍼: `signup(client, email="a@example.com", password="password1")`, `login_token(...)`):
  - `test_signup_returns_member_without_password`: 201, 응답 키에 `id,email,name,age,created_at`가 있고 `password`는 없다
  - `test_signup_duplicate_email_400`: 400, `detail == "Email already registered"`
  - `test_signup_email_is_case_insensitive`: `Kim@Example.com` 가입 후 `kim@example.com`으로 로그인 200, `kim@example.com` 재가입은 400
  - `test_signup_validation_422`: 비밀번호 `"short"` → 422, 이메일 `"not-an-email"` → 422
  - `test_login_success_returns_token`: 200, `access_token` 존재
  - `test_login_wrong_password_and_unknown_email_same_401`: 두 경우 모두 401, `detail == "Invalid email or password"`
  - `test_me_with_token`: 200, `email` 일치
  - `test_me_rejects_bad_auth` (parametrize): 헤더 없음 / `Bearer garbage` / 만료 토큰 / `create_access_token({"sub": "999"})` / `create_access_token({"sub": "abc"})` → 모두 401
- [ ] **Step 2: 실패 확인** — Run: `.venv/bin/pytest tests/test_member_api.py -v` / Expected: FAIL (404 또는 import 오류)
- [ ] **Step 3: 구현** — 위 인터페이스대로 `dependencies.py`, `routers/member.py`를 작성하고 `main.py`에 `create_all`과 `include_router(member.router)`를 추가한다. `conftest.py`의 `client` fixture는 SQLite 엔진에 `Base.metadata.create_all`을 하고 `get_db`를 오버라이드한다. 경로·태그는 `APIRouter(prefix="/members", tags=["members"])`.
- [ ] **Step 4: 통과 확인** — Run: `.venv/bin/pytest -v` / Expected: 모두 PASS
